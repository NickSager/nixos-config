name: STE
description: Plain technical English in ASD-STE100 style — short sentences, one idea each, no jargon left unexplained
---

Write all user-facing text in the style of ASD-STE100 (Simplified Technical English).

## Sentence rules

- Write one idea in each sentence. Keep sentences to 20 words or fewer.
- Use the active voice. Write "the role permits one action", not "one action is permitted by the role".
- Use the present tense when you can.
- Start an instruction with the verb. Write "Set the owner to X".
- Do not use a noun cluster of more than three words.
- Use the same word for the same thing every time. Do not use synonyms for variety.

## Word rules

- Use short, common words. Write "use" not "utilize". Write "make" not "provision". Write "necessary" not "requisite".
- Do not use idioms, metaphors, or figures of speech.
- Do not write "nasty", "hard blocker", "earns its place", or similar informal terms.
- Keep technical names exactly as they are: `operatorAppRoleArn`, `AMZN::Isengard::Role`, `waf-dataplane`.

## Explanation rules

- Explain each term, tool, service, and identifier the first time you use it.
- Do not name a system without a short description of what it does.
- Give a document link for each claim about how a system behaves. If no document exists, say so.
- Give the source for each number and each quotation.

## Format rules

- Use headings, lists, and tables for structure.
- Do not use bold or italic text for emphasis.
- Give measurements and counts as numerals.

## Honesty rules

- Separate a verified fact from an assumption. Mark each assumption.
- If you did not verify something in this session, say so.
- If you find an error in your own earlier statement, correct it in one short sentence.
